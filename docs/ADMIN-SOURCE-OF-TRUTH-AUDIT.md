# Borealis admin source-of-truth audit

This audit follows the current checkout. The previous Website workspace, booking management, notifications and dialog changes are included in the working baseline.

| Area | Editor and stored source | Reader and audit result |
| --- | --- | --- |
| Standard nightly rates | Rooms & Rates → Rates. A base-rate form writes the current `rates` row per room type. Room creation can seed the initial rate. | Public room prices read active visible base rates. The booking engine uses the same rate row as the starting point for the date-specific quote. Removed the Rooms quick form and existing-room price inputs. Room publication can activate the initial draft rate without rewriting its amount, currency or active flag. |
| Seasonal rates and rules | Rates writes `seasonal_rate_periods`, its room assignments and `pricing_rules`. The former rate-rules entry points to Rates. | Date-specific pricing and stay restrictions are applied by the quote and hold engine. Season and rule controls remain separate from the base rate. |
| Physical inventory and blocks | Rooms sets occupancy and inventory units. Availability creates or reopens `availability_blocks`. | Room and date checks use published units, occupancy and blocks. Rate rules constrain pricing and arrivals through a separate workflow. Availability links are shortcuts. The precheck now ignores expired holds, matching the database guard. |
| Bookings and inquiries | Bookings owns staff reservations, lifecycle actions and review of guest changes. Guest inquiries use their existing inbox. | Staff bookings, guest holds and confirmations use separate entry points and share reservation validation. Guest review requests remain separate from an actual booking change. |
| Contact | Property Settings writes the `properties` contact columns. Website → Contact writes page copy and directions in its CMS document. | Homepage, footer, Contact and the floating WhatsApp control use the shared contact reader. Existing null channel values may still render the corresponding published legacy value. Property Settings displays that value before save. An explicit blank takes precedence over legacy copy. |
| Website editors and navigation | Website edits page documents, Homepage CMS sections, and `navigation_items`. `/admin/pages` redirects to Website. | Public renderers use published content. The Website links to room, offer, media and property editors for operational records. The existing header combines Experiences with Transfers and Gallery with Contact. |
| Offers and service inventory | Experiences & Transfers owns offer records, offer images, schedules and rental settings. Website owns the listing-page copy. | Standalone offers and room add-ons use their existing service-specific rules. Transfer capacity is a per-request limit, with no shared fleet inventory demonstrated. Rental timing and receipt controls remain separate from stay settings. |
| SEO | SEO owns `site_settings` defaults and `page_seo` overrides. Entity editors own `seo_metadata`. | Fixed-route SEO now uses the actual public URL. Gallery & Contact uses the existing Contact SEO record. Transfers listing metadata stays with the combined Experiences route. The SEO overview links to entity editors. Explicit canonical overrides remain available. |
| Media and branding | Media Library owns `media_assets`, metadata and archive controls. Page and entity pickers save asset references. | Cover images, sharing images, focal positions and alt text serve distinct roles. Gallery membership still comes from `gallery_items` and published media. Existing Borealis branding assets remain in use. |
| Stay booking policy | Property Settings writes `booking_mode`, `booking_hold_minutes`, `minimum_advance_hours`, `maximum_booking_horizon_days` and age bands. Website → Booking page owns the introduction. | The engine applies mode on confirmation and duration and date limits on holds. Guest search can still show dates that the hold window later rejects. The optional property notice now renders above the booking form. Room occupancy remains per room. Age bands label guest categories. |
| Inactive and informational settings | Existing values remain stored. Property Settings identifies operational payment flow and reference details. | Property-wide guest maximum and minimum booking-holder age have no enforcement consumer. Deposit and online collection have no implemented provider. Check-in time, check-out time, coordinates and property timezone are reference fields. |
| Cancellation and notifications | Property Settings owns cancellation policy text and notification preferences. Notifications owns device enrollment. | Policy wording appears in Manage booking. Automatic cutoffs are separate and staff review remains the default. Enabled event types create alerts. Owner email additionally requires configured Resend delivery and recipients. Staff push uses per-device enrollment. Guest confirmation appears on screen. Automatic guest email is unavailable. |
| Languages | Languages owns locale preferences and translations. Editor translation links are shortcuts. | Enabled languages and translations are read through the public language services. A translation is a language-specific override, with base content retained. |
| Integrations | Settings → Integrations and calendars links to Channels. The owner manages calendar mappings and sync. | Calendar imports feed availability. Export feeds use private calendar links. Calendar configuration does not enable online payments or email delivery. |

## Compatibility and decisions

No migration is required for the contact compatibility path. Historical null values are ambiguous. They still receive the old published fallback until explicitly saved in Property Settings. A deliberate clear now saves an empty canonical value. The same reader respects both legacy-only records and conflicting canonical values. Saved Contact draft values do not participate in that compatibility path.

The old room sidebar already used date-specific availability wording in this checkout. Its payment wording now applies to both request and instant modes. The Rooms landing description comes from Website. No new commercial defaults or collection provider were introduced.
